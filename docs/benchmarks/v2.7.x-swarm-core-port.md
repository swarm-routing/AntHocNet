# v2.7.x swarm-core port: the standard cells before and after the move

[← Benchmark index](../benchmarks.md) · [Methodology](methodology.md#reproducing-via-ci-manual-dispatch) · [ADR-0029](../adr/0029-anthocnet-builds-on-swarm-core.md) · [v2.7.x image control](v2.7.x-image-control.md)

AntHocNet moved onto swarm-core in slices S0–S11 (#1019,
[ADR-0029](../adr/0029-anthocnet-builds-on-swarm-core.md)). Each slice was to
change no arithmetic and no order (maintainer decision Q2, 2026-11-15: aim for
byte identity of every standard cell). The CI ns-3 jobs of every slice printed
the same `##RUN##` lines as `main` before it. They are short runs, so this
campaign is the slow check: one cell per family, 20 seeds, run on `main` before
S1 and on `main` after S10d.

**Verdict (2026-11-16): not byte-identical.**
- Four families are identical: static mesh, the ISL grid, LEO and SAGIN.
- Four MANET families differ in their `anthocnet` rows on some seeds: grid,
  FANET, VANET and disaster.
- The stock arms' per-run rows and the oracle's are identical everywhere. Their
  `##COMMON##` rows follow the `anthocnet` change.
- **Cause and fix ([#1080](https://github.com/swarm-routing/AntHocNet/issues/1080),
  [#1083](https://github.com/swarm-routing/AntHocNet/pull/1083)):** S10a's
  control sockets sent unicast ants with TTL 1, so an ant relayed through a
  gateway was dropped. #1083 sends them at ns-3's default TTL again, which
  restores the pre-port rows on every seed that differed (see
  [Resolution](#resolution)). The cells below are the port as it was at
  `c919528`, before #1083.

  generation `port1019`, dispatched and collected with `ns3-campaign`
  (swarm-routing/ns3-tools).
- **Cells:** the eight families of the

  `static-mesh`, `fanet-main`, `vanet-sparse`, `disaster-main`, `sat-failcell`,
  `leo-walker16-anthocnet` and `sagin-walker16-anthocnet`.

    blocks as that control splits them.
  - A run depends on its seed alone (#352).
- **Image base:** both arms were built by `campaign-image.yml` on one base,
  `ghcr.io/swarm-routing/ns3-dev:3.48-optimized@sha256:5585a93c5cea1980592539e2d26a4e111e0ff4b0cc63b3dfd6ea5de459d80d3f`.
  The release is 3.48 while #843 is open, because aodv is an arm.
- **Harness:** both arms run swarm-routing/ns3-tools v1.1.2, so every arm runs
  in its own process (`--isolateArms`, its default).

  S0 (C++23, #1024) is in both arms.

- **Read:** `python3 tools/bench/harness_control.py tools/bench/campaigns/v2.7.x-swarm-core-port.yaml`.
  It compares each cell's base file with its `source`, the port arm's file,
  on every `##RUN##`, `##ROUTE##` and `##COMMON##` row of every seed. The
  table below compares every other line too. It leaves out the first line,
  which `ns3-campaign collect` writes with the run ids and `source_sha`;
  `##PROV##`, which names the commit and image and so differs by
  construction; and `##PERF##`, which is timing. "Differing" counts the lines
  present in one file and not in the other, as a multiset:

  ```bash
  python3 -c 'import collections as C,sys
  r=lambda p: C.Counter(l for l in open(p) if not l.startswith(("# port1019 ","##PROV##","##PERF##")))
  b,p=r(sys.argv[1]),r(sys.argv[2]); print(sum(b.values()), sum(((b-p)+(p-b)).values()))' \
    results/cells/fanet-main-port1019.txt results/cells/fanet-main-port1019-port.txt
  ```

- **Which lines differ.** On a seed that differs, every `anthocnet` per-run
  line differs: `##RUN##`, `##ROUTE##`, `##AIR##`, `##GOODPUT##`, `##HOLD##`,
  `##REINJ##`, `##DROPID##`, `##MATCH##` and `##ENERGY##`.
- **`##COMMON##`.** Every protocol's `##COMMON##` row of that seed differs
  too. It is computed over the flows every protocol delivered, so it follows
  the `anthocnet` change.
- **The other arms.** Every per-run row of aodv, olsr, dsdv, aomdv, hwmp,
  gpsr, gpcr, gpsr3d and oracle is identical. Only their `##COMMON##` rows
  differ, on the seeds where `anthocnet` differs, as stated above.
- **Size.** Per seed, PDR moves by at most 0.9 pp (FANET seed 6). The mean
  change per cell is within ±0.07 pp.

What is known so far:
- Only the Wi-Fi families with mobility and link breaks differ. The static
  mesh, which uses Wi-Fi but holds its links, and the point-to-point ISL,
  LEO and SAGIN cells are identical.
- That pointed to a path only link breaks exercise. The bisect on #1080
  found it in S10a instead: the TTL of unicast ants.

## Resolution

- **Bisect.** FANET seed 6, run with `anthocnet` alone, gives the `base` row
  at `aa8eedd` (after S9) and the `port` row from `fa9776c` (S10a) on. S1–S9
  change nothing.
- **First divergence.** ns-3 logs of both builds are identical until
  t = 55.918868736 s. A unicast ant from 10.1.0.13 to next hop 10.1.0.23 is
  routed through gateway 10.1.0.29 in both. Before S10a the gateway relays it
  (TTL 64). From S10a on it drops it as TTL-exceeded, because the base's
  control sockets send with TTL 1.
- **Fix.** [#1083](https://github.com/swarm-routing/AntHocNet/pull/1083):
  unicast ants leave by a socket of the adapter at ns-3's default TTL.
- **Check.** With the fix, all 37 seeds whose `anthocnet` lines differed
  match the `base` cell on every per-run `anthocnet` line:

  | family | seeds |
  |---|---|
  | grid | 3/3 |
  | FANET | 9/9 |
  | VANET | 18/18 |
  | disaster | 7/7 |

  `##COMMON##` and `##MATCH##` are left out of that comparison because they
  are computed across arms. The families that were already identical stay
  so: static mesh seeds 1–2, ISL seeds 1–20 and LEO seeds 1–3.

**Plausibility.** In both arms, 3 of the 4 static-mesh blocks fail
`scenario_check` on `delay99 1.5 < mean delay`. The rows are identical, so the
failure is not a difference between the arms. It is
[#1081](https://github.com/swarm-routing/AntHocNet/issues/1081).
